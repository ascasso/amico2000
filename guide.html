How to use the AMICO 2000

A keypad, six red digits, and 6502 machine code. The monitor is the small built-in program that lets you inspect memory, enter bytes, and start your own programs.

Getting started Keypad and memory File formats Cassette LOAD/SAVE Troubleshooting

Getting started

The emulator starts running automatically with the monitor ROM already installed. You do not need to load a file to use it. Click or tap the board's keys, or use the keyboard shortcuts below.

The four digits on the left normally show an address; the two on the right show the byte at that address. Everything is hexadecimal: digits 0-9 and A-F. A dollar sign marks a hex value, so $0200 is an address and $EA is a byte.

  • RES (Escape or Backspace) returns to the monitor, even from a stuck program, and keeps RAM.
  • Cold reset clears the emulator's 2 KB of RAM. Use it when you want to start over.
  • The bench Stop/Run button pauses or resumes the processor. Leave it running to use the keypad: the monitor must execute to read your keys.
  • Step executes one CPU instruction while paused. The Processor state panel shows the CPU's live registers.

The board's RUN key starts a user program through the monitor. The bench Run button resumes the emulator after a pause. RES and Cold reset do not resume a paused emulator.

Inspect or change a byte

  1. Press RES, then AD and four address digits, for example 0 2 0 0.
  2. Press DA, then two digits to write a byte, for example E A (the 6502 NOP instruction).
  3. Press Increment to move to the next address. Enter the next two digits; DA mode remains selected.
  4. To inspect another location, press AD and its four digits. Increment lets you walk through successive bytes.

Use $0000-$07FF for the board's RAM. ROM locations are read-only; typing data there cannot modify the monitor.

Enter a small program

At $0200, enter these seven bytes, pressing Increment between bytes:

A9 42 85 20 4C 22 FE

This program stores $42 at $0020, then jumps back to the monitor. Select its start with AD 0 2 0 0, then press RUN. Inspect $0020 with AD to see the result.

If the keypad sequence does not produce the expected result, use the console example below; use RES to recover from a running program.

What files can I load?

Choose Load ROM or tape on the home page. The picker offers .bin, .rom, .ic9, .ic10, and .amtape files.

ROM and program files are raw binary bytes, without a header or an embedded load address. A text file containing A9 42, an assembly listing, or an Intel HEX file must be converted to raw binary first. Renaming it does not convert it.

Name contains ic10 or cassette Installs a cassette ROM at $FB00, then cold resets. A complete image is 512 bytes; larger files are rejected.
Any other 512-byte fileInstalls it as a monitor ROM, then cold resets, even if the extension is .bin.
Other raw binary filesCopies bytes to $0000 without resetting or starting the program. Select its entry address and use RUN afterwards.

Names are matched without regard to case, in the order above. A name containing tape is also treated as a tape image before any ROM or size checks. Use names such as prom.ic9, prom.ic10, or program.bin to avoid accidental classification. Short ROM files are accepted as partial writes, so use a complete 512-byte dump to replace a PROM.

Loading either ROM clears RAM. For a raw program requiring another load address, or a 512-byte program that would be mistaken for a ROM, use the console method below.

Load and run at a chosen address (console)

Open your browser's developer console. This example loads and runs the seven-byte program above at $0200:

amico.stop();
amico.res();
amico.loadProgram(new Uint8Array([0xA9, 0x42, 0x85, 0x20, 0x4C, 0x22, 0xFE]), 0x0200);
amico.cpu.PC = 0x0200;
amico.start();
debug.mem(0x0020, 1);

Run debug.mem(0x0020, 1) after execution to see 42. For your own program, substitute its bytes, load address, and entry address. Do not cold reset between loading and running.

Cassette LOAD and SAVE

An .amtape is the emulator's binary cassette format, containing a program identifier, recorded address range, program bytes, and checksum. It is produced by this emulator; it is not a WAV/MP3 recording or a raw ROM dump. Audio recordings need a separate decoding step before they can be used here.

The emulator intercepts the cassette entry points directly, so these file operations do not require an additional cassette ROM. They return to the monitor after the operation.

LOAD an imported tape

  1. Choose the .amtape with Load ROM or tape. Its identifier and recorded addresses are logged in the browser console.
  2. Enter its identifier at $0000. For the recorded load address, put 00 at $0001 and FF at $0002. To relocate instead, put the desired address's low byte at $0001 and high byte at $0002.
  3. Select $FC54 with AD and RUN to perform LOAD. This loads bytes; start the program separately at its entry address.

For example, to LOAD tape identifier 01 at its recorded address through the console:

amico.stop();
amico.res();
amico.writeMemory(0x0000, 0x01);
amico.writeMemory(0x0001, 0x00);
amico.writeMemory(0x0002, 0xFF);
amico.cpu.PC = 0xFC54;
amico.start();

A missing identifier or a destination overlapping ROM causes LOAD to fail with FF at $0000. Inspect the destination bytes before starting the program.

SAVE and download a tape

Enter the start address's low/high bytes at $0000/$0001, the inclusive end address's low/high bytes at $0002/$0003, and the identifier at $0004. For $0200-$0206 with identifier 01, these five bytes are 00 02 06 02 01.

RUN from $FBBC to SAVE. Once back in the monitor, execute debug.saveTape() in the browser console to download an .amtape file. SAVE alone keeps the record only in the current page session; download it before closing or reloading the page.

To save the example program through the console, after loading it at $0200:

amico.stop();
amico.res();
amico.writeMemory(0x0000, 0x00);
amico.writeMemory(0x0001, 0x02);
amico.writeMemory(0x0002, 0x06);
amico.writeMemory(0x0003, 0x02);
amico.writeMemory(0x0004, 0x01);
amico.cpu.PC = 0xFBBC;
amico.start();

Then run debug.saveTape() to download the result.

If something goes wrong

  • Keys do nothing: resume with the bench Run button, then press RES. On a narrow screen, scroll the board sideways to reach all keys.
  • A program is stuck: press RES. If the monitor still fails, Cold reset restores its RAM setup and clears your program.
  • A file does not load: read the error alert and check its name, byte count, and format. A 512-byte program uses the ROM fallback; a renamed audio or text file is not a binary tape or ROM.
  • Need to inspect memory: in the browser console, use debug.mem(0x0200, 16) or debug.state(). After using console start/stop commands, the bench button label may be out of sync; use amico.start() to resume.
  • Work disappeared after a reload: RAM and imported tapes are held in this page session. Save and download a tape to keep a program.
