## The Handheld Layout on Tablets Held Upright

### Purpose and scope

The home page build stamp advances to 2026-11-23 with this commit.

The owner tried the page on two more devices. In Chrome on a OnePlus 7T, an
Android phone held upright, the handheld layout looked right and everything
worked. On an iPad Pro 11" held upright the page showed the board as drawn,
with keys and displays "pretty small"; in landscape it "looks ok".

The layout's media query stopped at 640 px. That left tablets out on
purpose, on the reasoning that a screen the board fits should keep the
board, and `tests/handheld-layout.test.js` held the width below the board's
minimum of 760 px for that reason. The iPad shows the reasoning was wrong:
the board fits, but too small to use with a finger.

Measured in headless Chrome, emulating each size as a touch screen:

| iPad Pro 11" | 834 px | 32 px | 188 px | 99 px | 480 px |
| iPad Pro 13" | 1032 px | 39 px | 235 px | 114 px | 480 px |
| iPad Pro 11", landscape | 1194 px | 45 px | 268 px | (not used) | |

Landscape, at 45 px a key, is what the owner found fine, so the line falls

## Checking the Site for Search Engines

### Purpose and scope

The owner asked for the site to be checked for search engines. The live
site was fetched with `curl`, and rendered in headless Chrome with
Googlebot's phone user agent, at `https://ascasso.github.io/amico2000/`.

### What was wrong

**The repository's documents were published as web pages.** The Pages build
is the legacy one, from `master`, and with no `.nojekyll` it runs Jekyll.
Jekyll leaves an HTML file without front matter alone, which is why the
three pages are served byte for byte as committed, but it renders every
Markdown file: `/AGENTS.html`, `/NextSession.html`, `/CHANGELOG.html`,
`/docs/logs/2026-11-23.html`, `/docs/monitor-rom-review.html`, the text of
the supplement and the rest answered 200 as pages in the default theme, each
with a title such as "AGENTS.md | amico2000", the repository's description
and a canonical address of its own. 22 of the 26 Markdown files; the other
four are READMEs, three of which are served as their folder's index.
Nothing on the site links to them, so Google may never have found them, but
a single link from anywhere would put the guidance for agents into the
results for the machine's name. `robots.txt` said the rest of the repository
"is not served as pages".

Fixed with an empty `.nojekyll` at the root. The documents are then served
as the plain files they are, and stay readable on GitHub. `_config.yml` with
an `exclude` list would have taken them off the site altogether, at the cost
of a build to configure where the project has none. It takes effect when
`master` has it.

## Compiling a byte language for the original board

The owner chose the small language sketched for the AMICO and asked for both
assembly and machine code, with the monitor's known bugs taken into account.
The first compiler runs in Node.js. Code and tables fit below the vectors on
a 1 KB board. A listing pairs each instruction with its address, bytes and
source line. The cassette output uses the emulator's own record writer so
the monitor can load the image at its linked address.

The ROM remains the reference. Startup clears D, TASTO gets Port A as an
input, and normal exit enters the monitor through its initialization. A
program can request a shared debounced input routine that scans the displays
while it waits. The compiler guide records the two branch-calculator defects
that a user can still encounter at the monitor.

The square-table program occupies 40 bytes at $0200-$0227. The eight compiler
tests cover all sixteen keys through the monitor after a tape LOAD and a RUN
with D set in the saved status, held and bouncing keys, branch distances,
zero-page temporaries, and the 508-byte limit. All 245 repository tests
passed. Independently assembled the listing with 64tass 1.60.3243 in a
temporary directory and compared the binary byte for byte. Syntax and diff
checks passed. Machine checks used the emulator in Node; a physical board
and the browser file picker were not exercised.

## Playing the matchstick game in the byte language

Added a complete game to exercise the language beyond a lookup table.
The manual supplies the rules and the six-digit arrangement. This version
has a fixed opening reply and uses the debounced input routine instead of
the original delay. It occupies 186 bytes at $0200-$02B9 and uses five bytes
in zero page, including the helper's two. The candidate transcription of
the original listing occupies 148 bytes.

The regression check starts the game with the monitor keypad, rejects 0 and
F, plays a winning and a losing sequence, checks each remaining total, and
reads both final patterns from the emulated displays. All 246 tests passed.
64tass 1.60.3243 assembled both examples to binaries identical to the
compiler's output. JavaScript syntax and diff checks passed.

## Naming the Language Amico and Settling Its Design

The compiler of the two entries above began, the owner said, as a thought
experiment: asked whether a small language for the board was feasible, Codex
built the whole of it in one prompt. The owner then asked a second agent for
its thoughts on the language, for a name, and for a conversation about
improving it before anything was changed. This entry records that
conversation. No code changed.

**The first look.** The agent read the three files, ran the nine compiler
tests, and wrote three programs from the README alone: a 24-hour clock of 140
bytes, a die of 49 and a hex entry of 97. Each ran correctly on the emulated
board the first time, started with the monitor's own keys. The clock's
second came to 999,960 CPU cycles. What it found is in `NextSession.md`,
item 13: the language is honest about cost and knows the monitor's faults,
and it reaches the hex digits and the keypad and nothing else.

**The name.** The owner chose Amico, with source files ending in `.amico`
and the compiler `amicoc` as it was. Adda, Otto and Caro were offered first
and refused; Adda, from the keys AD and DA, would be taken for Ada.

**What the owner settled.** All of it is in item 13, with the owner's words:
the direction ("fairly simple", "optimized for this board, not a generic
portable language"); what is to be added, among it names for memory
locations, calls, tables written out, a decimal block, words for the
displays, a routine for the HLT key and subroutines; what stays out, Italian
words in the language among it; and that a program longer than 508 bytes
will step over the vectors at `$03FC`, built when one first needs to. The
words for ending a loop are still to be chosen. The owner also said that the
North Star's test, that help must not make the machine easier than it was,
is about the emulator; Amico is a tool beside it.

**Read on the scan for it**, at 110 to 300 dpi, PDF page numbers and printed
ones being the same in the supplement:

## Checking the Compiler as It Stands

The owner asked for a check of the compiler before anything was built on it,
read only, run "with subagents with different models" and one Codex instance
on Astra. Its findings are in `NextSession.md`, item 13, and the way it was
run is in `AGENTS.md`, A Review by Several Agents, which the owner asked for
afterwards. This entry has what belongs to neither.

**Who looked at what.** One brief for all; one angle and one model each;
all five at once, in the background, each in a scratch directory of its own:

- Claude Opus built a differential tester: an interpreter written from the
  README alone, a random generator of valid programs, and a runner that
  starts each program on the emulated board with registers and flags
  randomised and compares the display bytes and every variable. 30,000
  programs generated, 22,332 of which fitted in 508 bytes and ran; 5,000
  more with `display.scan()` among the statements, 3,615 of which ran. No
  mismatch.
- Claude Fable read `compile.js` line by line and tried each suspicion on
  the board. It wrote an oracle for the assigned-on-every-path rule that
  works on a control-flow graph and tried every nesting of `if`, `else`,
  `loop` and `stop` up to seven statements; compared the compiler with a
  copy that never trusts the accumulator; and disassembled `$FEEB`, `$FF0C`
  and `$FF57` to check the key helper. It found the 257-byte image and the
  RUN after HLT.
- Claude Sonnet took `emit.js` and `amicoc.js`: every opcode, a branch at
  each distance from 122 to 132 bytes, the limits, and an assembler of its
  own for the listing's text, which gave the compiler's bytes back for 1,102
  programs.
- Claude Haiku took the README sentence by sentence.
- Codex on Astra took the whole compiler and came back with six findings in
  nine minutes.

**What the session running them did.**

- Reproduced each finding with a script of its own or the reviewer's.
- Ran 3,000 more random programs with seeds the tester had not used: no
  mismatch.
- Planted five defects in scratch copies of the compiler and ran the tester
  against each. It caught a missing `forget()` at `else` and `end`, a stale
  accumulator after an operation, and one after a table read. It missed a
  wrong join of assigned names, which a test of valid programs cannot see,
  and a missing `forget()` at a loop head: its loops count down in a
  variable that is in the accumulator on the way in and on the way back
  alike. Six programs written by hand, in which the two differ, pass on the
  compiler and five of them fail on that copy.
- Followed `compiler/README.md` on the page as served, in headless Chrome
  over the DevTools protocol: `squares.amtape` picked in the file input,
  the alert read ("Loaded: squares.amtape (58 bytes)"), the LOAD and the RUN
  clicked on the on-screen keys, `64` for A and `E1` for F; then
  `matches.amtape`, which replaces program 01 on the cassette, RES, the same
  keys, `0000 21`, a move, and the game to `DEAD 01`. A raw `.bin` picked
  there lands at `$0000`, as the README warns. Without RES the keys for the
  second LOAD go to `squares`, which is still running.

**Not done.** 64tass is not installed. Codex had built a copy in a temporary
folder when it wrote the compiler and used it again here; the session was
not permitted to run that copy, and reports Codex's result as Codex's. The
only console message in the browser was the 404 for `favicon.ico`, which is
item 12's.

**A correction to what was said in conversation.** The owner was first told
"about 38,000 random programs", the reviewer's headline. That is how many
were generated across its campaigns and probes. About 26,000 ran; the rest
were too long for the board and were refused, rightly.

No code changed. Verification: `git diff --check`, `node --test tests/`.

## A Net Under the Compiler: Random Programs Against a Reference Interpreter

The owner agreed to keep the check's two best harnesses as tests, before the
compiler's front end is reworked. This is the first: the differential tester
that Claude Opus wrote as a reviewer, rewritten for the repository.

- `tests/helpers/amico-reference.js` is an interpreter for the language as
  `compiler/README.md` describes it. It shares no code with `compiler/`, and
  says at its head that it must not.
- `tests/helpers/amico-programs.js` makes a valid program from a seed, and
  says what it leans on and what it cannot make.
- `tests/compiler-differential.test.js` compiles each program, runs it on
  the emulated board from `$0200` with junk in the variables, A, X, Y and
  the flags, decimal mode set on every other run, and stops it at `$FE22`.
  The display bytes and every variable with a place in the listing have to
  be what the interpreter says, and no other byte of RAM may have changed.
  A second test puts `display.scan()` among the statements. A third has six
  programs written by hand in which the accumulator holds one thing on the
  way into a loop and another on the way back.
- The test also counts what the generator made, long branches, loops, table
  reads, `else` arms and `if`s four deep, and fails if any falls to half of
  what it was: a generator can go quiet and leave the test passing.

A thousand programs by default, of which about 730 fit in 508 bytes and run,
in 0.6 s. `AMICO_PROGRAMS=30000` took 20 s.

Verification. The test passes on the compiler as it is, at 1,000 and at
30,000 programs. Run against four scratch copies of the compiler with one
defect planted in each, it fails on all four: the random programs catch a
missing `forget()` at `else` and `end`, a stale accumulator after an
operation and one after a table read, and the six loop programs catch a
missing `forget()` at a loop head, which the random ones pass. `node --check`
on the three files, `node --test tests/` with 249 passing, `git diff --check`.
