## Compiling a byte language for the original board

The owner chose the small language sketched for the AMICO and asked for both
assembly and machine code, with the monitor's known bugs taken into account.
The first compiler runs in Node.js. Code and tables fit below the vectors on
a 1 KB board. A listing pairs each instruction with its address, bytes and
source line. The cassette output uses the emulator's own record writer so
the monitor can load the image at its linked address.

The ROM remains the reference. Startup clears D, TASTO gets Port A as an
input, and normal exit enters the monitor through its initialization. A
program can request a shared debounced input routine that scans the displays
while it waits. The compiler guide records the two branch-calculator defects
that a user can still encounter at the monitor.

The square-table program occupies 40 bytes at $0200-$0227. The eight compiler
tests cover all sixteen keys through the monitor after a tape LOAD and a RUN
with D set in the saved status, held and bouncing keys, branch distances,
zero-page temporaries, and the 508-byte limit. All 245 repository tests
passed. Independently assembled the listing with 64tass 1.60.3243 in a
temporary directory and compared the binary byte for byte. Syntax and diff
checks passed. Machine checks used the emulator in Node; a physical board
and the browser file picker were not exercised.

## Every Small Program Against an Oracle for the Two Flow Rules

The second harness kept from the check, Claude Fable's, rewritten for the
repository as `tests/compiler-assignment.test.js`.

The random programs of the entry above are all valid, so they say nothing
about what the compiler should refuse. This test makes every program of up
to five statements out of an assignment, a read, `stop`, `loop` and `if`
with and without `else`, nested up to three deep, over one name, and every
one of up to four statements over two names: 35,662 and 9,136 programs. For
each, an oracle says whether it is valid and, if not, the line of the first
statement that is wrong and why.

The oracle does not work as the compiler does. The compiler walks the
source, keeps a set of assigned names, and intersects two sets where the
arms of an `if` meet. The oracle builds a graph of statements, finds what
can be reached by search, and finds the names certainly assigned at each
node by going round the graph until nothing changes. A loop is an edge back
to its first statement; `stop` is a node with no way out.

The compiler has to agree on all of them: accept the 5,974 and 1,844 valid
ones, and refuse each of the others with "Line N:" for the same line and
with "Unreachable statement" or "assigned variable" in the message. The test
also holds the four counts, so that an enumerator which stopped short would
be noticed. 0.3 s. `AMICO_STATEMENTS=7` is 4.1 million programs.

Verification. Passes on the compiler as it is. Against a scratch copy in
which the arms of an `if` are not intersected, so that a name assigned in
one arm counts as assigned after both, it fails. `node --check`,
`node --test tests/` with 251 passing, `git diff --check`.

## A 257-Byte Program and the Cassette PROM

The first of the check's findings to be fixed (`NextSession.md`, item 13).

The cassette PROM loses the last byte of a block one byte longer than a
whole number of pages (`AGENTS.md`, Cassette Sound Format). The emulator has
always known that: the sound codec notes it and the traps keep the byte on
purpose. The compiler did not, and when a program came to exactly 257 bytes
its last byte, the high half of the closing `JMP $FE22`, never reached the
board through the real routine. Loaded with Cassette: Real time, such a
program ran into `JMP $0022`.

`emit.js` now lays the image out, and if its length is one more than a
multiple of 256 adds one `$EA` after everything else and lays it out again.
Nothing executes the byte, and adding it at the end moves nothing. The
listing says what it is for. `$EA` is what the manual's own long listing
fills with, before the vectors (supplement, page 99). On this board the only
such length under the 508-byte limit is 257; the rule is written for any,
since programs that step over the vectors will reach 513 and beyond.

The test builds a program of 257 bytes (CLD, three scans, sixty-one
assignments and the JMP), checks that it comes out at 258 with the filler
last and that programs of 256 and 258 bytes are left alone, and loads it
with the PROM's own LOAD routine against the emulated recorder: all 258
bytes arrive. Then it loads the same image without its filler, and the last
byte does not arrive, which is the fault itself.

Verification: `node --check compiler/emit.js`, `node --test tests/` with 252
passing, `AMICO_PROGRAMS=5000` on the differential test, `git diff --check`.

## A Source File With CR-Only Line Endings

The second finding. `compile.js` split its source at LF, with an optional CR
before it. A file whose lines end in a CR alone, which is how Mac OS wrote
text until 2001 and how some editors still can, was therefore one line. Two
things followed. A `#` anywhere in it made a comment of the rest of the
file, statements included, and the compile went through with a program cut
short. Without a `#`, the one line matched nothing and the error message
quoted the whole file.

The split is now at CR LF, at CR, or at LF, in that order, so that CR LF is
one ending and not two. Line numbers in errors count CR lines as lines.

The test compiles `squares.amico` with each of the three endings and wants
the same 40 bytes; compiles two assignments with a comment on the first,
ended by CRs, and wants both in the code; and wants an error on the second
CR line to say "Line 2".

Verification: `node --check compiler/compile.js`, `node --test tests/` with
253 passing, `git diff --check`.

## Three Messages That Named the Wrong Mistake

From the check's fifth finding. Each of these was refused, rightly, with a
message that sent the reader to look at something that was not wrong.

- **A comparison with an operation on its right.** `CMP` wants the left side
  in A and the right side as one operand, so `if b + 1 == a` compiles and
  `if a == b + 1` does not. The message for the second listed the four
  operators, of which `==` is one. When the operator is one of the four and
  the rest of the line holds no other comparison sign, the message now says
  that the right side is one literal, variable or display field and that an
  operation, a table read or a key read goes on the left. `<=` and `>` still
  get the list of operators, which is what is wrong with them.
- **A word of the language as a name.** `byte = 7` and `in = keypad.read()`
  were "Invalid byte variable". The message now says the word is one of the
  language's.
- **A table declared twice**, and a table's name assigned to, which were the
  same "Invalid byte variable": "Table declared twice" and "is a table, not
  a variable".

`compiler/README.md` gives the rule for the two sides of a comparison and
lists the eleven words. The test reads the compiler's own list out of
`compile.js` and fails if the README lacks one of them.

Verification: `node --check compiler/compile.js`, `node --test tests/` with
254 passing, among them the oracle for the two flow rules, whose messages
were left as they were; `git diff --check`.

## A Misspelt Line After `stop`

Also from the fifth finding. The compiler asked whether a statement could be
reached before it asked whether the line was a statement at all. So `ennd`
on the line after a `stop` was "Unreachable statement": true of anything
there, and no help to someone looking for a missing `end`. The question
whether the line is one of the statements now comes first, and a line that
is none is "Unknown statement" wherever it stands. A real statement after
`stop` is unreachable as before, and the oracle test, which tries only real
statements, is unaffected.

Verification: `node --check compiler/compile.js`, `node --test tests/` with
