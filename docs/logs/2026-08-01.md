# Engineering Log — 2026-08-01

## Issue #22: NMOS 6502 Decimal SBC Negative Flag

### Summary

Corrected decimal-mode `SBC` so the negative (`N`) flag is derived from the
low byte of the binary subtraction result rather than from the BCD-adjusted
accumulator. Added a dependency-free Node regression test for the reported edge
case and updated the active project guidance and changelog.

### Rationale

The AMICO 2000 uses an original NMOS 6502, so arithmetic flags must match that
processor rather than later CMOS behavior or a simplified BCD implementation.
On the NMOS part, decimal `SBC` produces a BCD-adjusted accumulator and carry,
but `N`, `V`, and `Z` reflect the underlying binary subtraction.

The previous implementation assigned the adjusted accumulator before computing
`N` and then copied bit 7 from that adjusted value. BCD correction can change
bit 7, which makes the emulator take a different `BMI` or `BPL` branch from the
original hardware even when the numerical BCD result is otherwise correct.

Issue #22 provides a valid-BCD vector that exposes the mismatch:

- Inputs: `D=1`, `A=$00`, operand `$80`, `C=1`
- Binary subtraction low byte: `$80`, so NMOS `N=1`
- BCD-adjusted accumulator: `$20`, whose bit 7 is clear
- Previous emulator result: `A=$20`, `N=0`
- Corrected emulator result: `A=$20`, `N=1`

The implementation now calculates `N` from `binaryDiff & $80`. This is the
smallest change that restores the documented NMOS behavior while leaving the
BCD result and the existing carry, zero, and overflow calculations unchanged.

### Verification

The new regression test was run before the production change and failed with
`0 !== 1` for the `N` flag, confirming that it detected the reported defect.
After the fix, the following checks passed:

```text
node --test tests/cpu6502-decimal-sbc.test.js
node --check cpu6502.js
node --check amico2000.js
node --check main.js
node --check display.js
git diff --check
```

The targeted test checks the adjusted accumulator and all arithmetic flags for
the issue vector. It uses Node's built-in test runner and adds no dependency or
general-purpose test framework.

### Scope

This change does not alter binary-mode `SBC`, decimal adjustment, instruction
timing, cassette behavior, or other CPU instructions. A full Klaus Dormann
conformance run remains valuable future verification, but it was intentionally
not made a prerequisite for this focused hardware-fidelity correction.
