# Engineering Log — 2026-09-06

## Front-End Recreation of the ASEL Board

### Summary

Reworked `index.html` so the emulator's interface recreates the appearance of
the real AMICO 2000 board rather than presenting a generic dark panel with a
separate display box and keypad box. Purpose: this is a memorial project, and
the project owner asked for an interface that conveys the experience of using
the original hardware, not only its behavior.

Reference material was the set of board photographs and the PCB layout render
archived from ComputerHistory.it. The layout images are only 600px wide, so the
result is a reconstruction driven by those photographs rather than a
pixel-accurate reproduction.

What the page now renders as a single green PCB slab:

- Solder-mask green board with a copper routing layer, gold vias, plated
  mounting holes, a bus edge connector, and a `J1 EXP` expansion header.
- Power section: transformer, two electrolytic capacitors, and a 7805 with
  heatsink.
- Logic: 6502, 8255 (corrected below), 2716 monitor ROM, two 2114 RAMs, 74-series glue, a crystal
  can, and discrete resistors and ceramic capacitors.
- Five red indicator LEDs, two of which remain the existing `led-power` and
  `led-run` elements driven by `main.js`.
- The seven-segment display block, and the keypad in the arrangement printed on
  the real board:

```text
[NOR|SS] [RUN] [ ↑ ] [DA]        0 1 2 3
[ RES  ] [HLT] [REG] [AD]        4 5 6 7
                                 8 9 A B
                                 C D E F
```

Red keycaps for the hex digits and blue for the function keys, each sitting
inside its printed silkscreen legend box the way the original does, with the
keycap itself blank. `A.S.E.L. AMICO 2000` is silkscreened vertically at the
bottom-right edge.

The board interior is sized in container query units (`cqw`) so the whole
assembly scales as one object; below 760px the board pans horizontally instead
of reflowing, since a board is a fixed-proportion physical thing. The run/step/
reset controls, the register readout, and the shortcut reference moved off the
board into plain panels underneath.

### Scope and Compatibility

No emulator behavior was changed. The rework deliberately preserved the entire
DOM contract that `main.js` and `display.js` depend on:

- All fourteen element IDs (`btn-run`, `btn-step`, `btn-reset`, `btn-load`,
  `led-power`, `led-run`, `reg-pc`, `reg-a`, `reg-x`, `reg-y`, `reg-sp`,
  `reg-flags`, `rom-file`, `display`).
- The `.key` class and all 23 `data-key` values, unchanged.

Two presentational changes did land outside `index.html`:

- The `GO` and `PC` keys are now labelled `RUN` and `HLT` after the legends on
  the real board. Their `data-key` values still read `go` and `pc`, and the
  matrix positions in `amico2000.js` are untouched. The `HLT`/`pc`
  correspondence is inferred from position on the board and is **not** confirmed
  against the monitor ROM; this is worth revisiting alongside the existing
  keyboard-matrix cleanup, since `keyMap` currently has only three distinct
  function-key positions (`[2,1]`, `[2,2]`, `[2,3]`) for seven physical keys.
- `main.js` lost the `▶`/`⏸` glyph prefixes on the run/stop button label, to
  match the plain-text control panel. Four characters, label text only.

Two implementation details worth recording, because both were latent traps:

- `main.js` sets `button.style.transform = 'translateY(3px)'` on key press,
  which replaces any transform used for layout. The keycaps are therefore
  centered with `left`, not `translateX(-50%)`, or they would jump sideways when
  pressed.
- The pressed state is carried by `box-shadow` and `filter` rather than a
  transform, for the same reason.

### Verification

```text
git diff --check
node --check main.js
node --test tests/cpu6502-decimal-sbc.test.js
```

All passed. Beyond the standard checks, the reworked page was verified in
headless Chrome against a local `python3 -m http.server`:

- The emulator boots and runs: the display lights and `PC` advances.
- A scripted `elementFromPoint` hit test at the center of every key reported
  `HITTEST OK all 23`, confirming no keycap is covered by its silkscreen legend
  or by the copper trace overlay.
- Rendering was reviewed by screenshot at 1280px and at 900px.

The visual result itself is a matter of judgment and was reviewed and accepted
by the project owner.

### Follow-Up

The project owner asked what would bring the interface closer still. The agreed
direction, recorded here so it is not lost:

1. Find better source artwork before doing more hand-drawn CSS. The `docs/`
   Sperimentare supplement PDF may hold the published PCB layout at print
   resolution, since the magazine printed it for readers to etch. The Wayback
   CDX API may also hold larger captures of the image filenames that returned
   "not archived" at the timestamp used here.
2. Colour-separate and trace the PCB layout render into SVG, and use it as the
   board's base layer, so components sit at true coordinates instead of
   eyeballed percentages.
3. A physicality pass: one consistent light source across all parts, a fraction
   of a degree of rotation per keycap, slight perspective tilt, flux residue and
   silkscreen mis-registration, and a grain and vignette overlay.
4. Render the six display digits as six separate DIP packages, which requires
   changes to `display.js`.
5. Sound: keycap click, transformer hum, LED flicker at power-on.

## Correct the I/O Package Identity

Replaced the incorrect `MCS 6532` marking in `index.html` with `8255`.
The package tooltip identifies IC15, the $FD00–$FD03 register range, and the
40-pin DIP; dedicated pin styling depicts twenty pins along each long side
instead of the generic fixed-pitch decoration. Placement and emulator behavior
are unchanged.

Evidence: `docs/computerhistory-amico2000.md:197-199` identifies the 8255;
`docs/manual-extraction/sperimentare-1980-05-supplemento-text.md` lists the
component at line 1424, maps IC15 at line 2273, and reproduces the 40-pin
8255A pinout on PDF page 76.

Verification: `git diff --check` passed. Inspected the HTML/CSS to confirm the
8255 label, two pin rows, and twenty repeats per row (5% background tile).
No JavaScript changed. Browser visual verification was not performed.
