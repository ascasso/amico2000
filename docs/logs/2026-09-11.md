# Engineering Log — 2026-09-11

## Require Small Commits in the Agent Contract

### Summary

The Agent Operating Contract asked for "one or more focused logical commits",
which permitted an agent to land an entire session as one commit and still be
within the letter of the rule. The project owner asked for small commits for
every unit of work, so the bullet was replaced with an explicit definition:
one commit is one unit of work, each commit stands on its own, and its
`CHANGELOG.md` and `docs/logs/` entries travel in the same commit.

### Scope

Guidance only. `AGENTS.md` and `CHANGELOG.md`. No source or behavior changes.

The subject-prefix rule records what the history already does rather than
inventing a new convention: `docs:` (11 commits), `fix:` (5), `ui:` (1) and
`feat(ui):` (1) are the prefixes in use, so those are the ones named, with
Conventional Commits as the general rule for anything new.

The existing `fix:` / `docs:` pairs — such as `43eb9c0` with `816e0b1` for
issue #31 — are explicitly still allowed: a large change may separate the code
from its longer-form documentation. The new rule forbids batching *unrelated*
units, not splitting one unit across a code and a docs commit.

### Verification

`git diff --check` passed. No JavaScript changed, so no `node --check` was
needed; `node --test tests/` was run for the session baseline and passed all
33 tests.
